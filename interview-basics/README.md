## Як розв'язувати: пояснюю на пальцях

**Тести писати не треба, вони вже готові.** Ти тільки замінюєш рядок `return todo();` на свій код.
`todo()` — це заглушка. Поки вона на місці, задача показується як ⏳ «ще не зроблено».

### Тип 1. «ПЕРЕДБАЧ»: повертаєш масив своїх відповідей

Над функцією є пронумерований список виразів. Тобі треба **в голові**, без запуску, вирішити, що поверне кожен з них. Відповіді запиши в масив **у тому ж порядку**.

Приклад (не з тренажера, просто показую механіку):

```js
// ПЕРЕДБАЧ — масив з 3 відповідей
//   [0] 2 + 2     [1] 'abc'.length     [2] typeof 'x'
function predictExample() {
  return todo();          // ← ДО
}
```

```js
function predictExample() {
  return [4, 3, 'string'];   // ← ПІСЛЯ: [0] → 4, [1] → 3, [2] → 'string'
}
```

Як записувати відповіді:

| Якщо результат... | пишеш у масиві |
|---|---|
| число | `4`, `-1`, `NaN`, `Infinity` |
| рядок | в лапках: `'string'`, `'51'`, `''` |
| boolean | `true` / `false` |
| undefined / null | `undefined` / `null` |
| масив | `[3, 3, 3]` |
| функція «кидає» назву помилки | рядком: `'TypeError'` |

Тест **сам обчислить** кожен вираз і порівняє з твоєю відповіддю **по одному**.
Помилка виглядає так:

```
❌  1. predictTypeof
     ▸ [4] typeof null          ← номер і сам вираз, де ти помилився
         очікувалось: 'object'  ← що насправді дає JS
         отримано:    'null'    ← що написав ти
```

Тобто прочитати це можна так: «у виразі №4 `typeof null` JS дає `'object'`, а ти написав `'null'`». Після цього перечитай теорію над задачею й зрозумій **чому**.

> Чесне правило: спершу заповни **весь** масив, а запускай уже потім.
> Помилка в передбаченні — це не провал, а саме те місце, яке треба запам'ятати.

### Тип 2. «НАПИШИ САМ»: звичайна функція

Над функцією описано, що вона має робити, і є приклади `виклик → результат`.
Видаляєш `return todo();` і пишеш реалізацію.

### Як читати тести (якщо цікаво, що там внизу)

Кожен тест — це пара **«що викликати» → «що має вийти»**:

```js
test('isNil', [
  [() => isNil(null), true],    // викликає isNil(null) і чекає true
  [() => isNil(0), false],      // викликає isNil(0) і чекає false
]);
```

- `() => isNil(null)` — «відкладений виклик»: тест сам натисне цю кнопку.
- `true` — правильна відповідь.
- Іноді є третій елемент, рядок-підпис. Він пояснює, що саме перевіряється.

Масиви й об'єкти тест порівнює **за вмістом**, а не за посиланням, тому `[1, 2]` і `[1, 2]` для нього однакові.

### Хочеш додати свій тест?

Допиши ще одну пару в потрібний `test(...)`:

```js
[() => isNil(false), false],
```

Запусти файл. Якщо твоя функція правильна, тест стане зеленим.
